# Phase 1.3-2 — Automatic Factur-X Attachment on Email Send

[← back to Phase 1.3 index](./README.md)

## Objective

Closes the "looking professional by default" gap from the 2026-08-25
review: today a FACTURE emailed to a client is the plain PDF unless the
artisan separately discovers and clicks "Facture électronique" first. With
`autoAttachFacturX` on, emailing a FACTURE attaches the Factur-X hybrid
automatically instead — the same file the manual button already produces,
just without the extra step.

## Decided/discovered during implementation (2026-08-24)

- **Catches any error, not specifically `UnprocessableEntityException`** —
  simpler than the plan's original narrower catch, and just as safe: the
  correct fallback (plain PDF) is the same regardless of why
  `generateHybridPdf` failed, so there's no benefit to distinguishing the
  error type here the way `FacturXService` itself distinguishes fatal vs.
  warning-level Schematron errors internally.
- **No live SMTP send verification was possible** — the Docker demo stack's
  seed companies have no SMTP credentials configured (Phase 12 is itself
  BYO-credential, same as SUPER PDP), so this phase's actual send path
  can't be exercised end-to-end in this environment. Verified instead via
  `invoice-mail.service.spec.ts`'s full branch coverage (on/off, FACTURE/
  DEVIS, success/failure) — same "unit tests cover it, live check wasn't
  re-run" precedent as Phase 1.2-4's own bug-check pass.

## Non-goals

- No change to the manual download/"Facture électronique" button — stays
  available regardless of this toggle, for getting the file without
  emailing it.

## Notes

- Independent of `autoTransmitViaPa`/PA connection entirely — attaching a
  file format to an email never talks to SUPER PDP, so this phase has no
  PA-availability gating to worry about, unlike 1.3-3/1.3-4.
