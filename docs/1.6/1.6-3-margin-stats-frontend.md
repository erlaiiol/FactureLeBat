# Phase 1.6-3 — Frontend: "Marge" Tab & Circular Breakdown Charts

[← back to Phase 1.6 index](./README.md)

## Objective

Surface [1.6-2](./1.6-2-margin-analytics-backend.md)'s `MarginAnalytics`
payload as a new tab in "Mon activité" (`stats-reports.page`), with the
donut/circle breakdowns the user explicitly asked for — "des cercles
statistiques qui représentent les bénéfices selon les produits/services ou
les clients."

### Frontend — new tab button

- [x] `stats-reports.page.html`: third button in the existing tab row

### Frontend — donut/circle chart component

- [x] New shared component, `margin-donut-chart.component.ts` (sibling to
      `revenue-bar-chart.component.ts`), stroke-dasharray ring technique,
      round line caps, a 2px-equivalent gap between slices, legend with
      label + amount + share for every slice, total centered inside the
      ring — matches `RevenueBarChartComponent`'s "small owned SVG
      primitive, no charting library" precedent.
  - **Correction vs. the plan**: this app had no existing multi-series
    categorical palette to reuse (only single-hue `fill-primary`, and this
    app's status colors — success/warning/danger — are reserved by the
    `dataviz` skill's own rule: "never reused for series N"). Added five
    new `--color-chart-1..5` tokens to `styles.css` (light + dark), chosen
    to avoid every one of this app's existing reserved hues (primary
    orange, danger red, warning amber, badge chartreuse) and validated with
    the skill's `validate_palette.js` — light mode passes all-pairs (the
    stricter standard, since every slice in a ring is visually adjacent to
    every other, not just its immediate neighbors) with a contrast WARN on
    two slots (mitigated by the always-on legend, the skill's own "relief
    rule"); dark mode passes on the adjacent-pairs standard at a
    specifically re-ordered slot sequence (blue, aqua, violet, magenta,
    green) — **that order is load-bearing, re-run the validator before
    reassigning slots**. Full reasoning in `styles.css`'s own comment.
- [x] One donut instance with a segmented toggle (produit/prestation/client)
      above it, not three separate charts — chosen for mobile width
      (confirmed live, see below) rather than assumed.

## Non-goals

- **No drill-down from a circle slice into the underlying invoices.** The
  existing "Mes produits"/"Mes clients" pages already let an artisan jump
  to a given item's invoice history; this tab doesn't duplicate that
  navigation, at least not in this pass.
- **No CSV export of margin data** — see the track README's "suggested
  extensions" backlog item.

## Notes

- Depends on 1.6-2's payload shape existing; can be scaffolded against a
  mocked payload before the backend is fully wired if useful, but should
  be live-verified against the real endpoint before this phase is marked
  done, same standard every other phase in this app holds itself to.
- **Live verification (2026-09-02, done)**: rebuilt `facturele-demo-*`
  (`make demo`) to pick up this track's backend changes, then drove real
  headless Chromium via Playwright (no `chromium-cli` in this
  environment, so a scratch script against the machine's already-cached
  Playwright browser instead) through the actual product form, invoice
  creation flow, and "Marge" tab as the seeded demo artisan
  (`demo.artisan@facturele.app`, `DEMO_MODE`'s one-click login). This is
  what actually caught the two bugs documented in
  [1.6-2](./1.6-2-margin-analytics-backend.md#two-more-corrections-found-live-against-the-real-demo-stack-not-caught-by-unit-tests) —
  neither was reachable from a mocked unit test. End-to-end proof: set a
  50% `PERCENTAGE` margin on a catalog product → created a real invoice
  billing 5 m² × 60,00 € = 300,00 € using it (via the actual "Ajouter un
  produit" catalog picker, not a freehand line) → marked it `PAYÉE` via
  the invoice board's status menu → reloaded "Marge" and got exactly
  150,00 € marge totale / 9 % taux moyen / 18 % couverture, a correctly
  proportioned single-slice donut, and a populated September bar on both
  monthly charts. All test invoices/products created during this pass
  were deleted afterward and the one demo product's margin reset to
  unset, via direct `psql` against the demo Postgres — confirmed the
  catalog/invoice board are back to their original seeded state
  screenshotted before cleanup.
